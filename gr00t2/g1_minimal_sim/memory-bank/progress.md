Each phase ends with explicit tests before the next. Prefer small PR-sized increments.

`spawn_g1_floor.py --stand --teleop` and `play_g1_gear_wbc.py --teleop` both drive `loco_cmd` via held W/S A/D Q/E with stand↔walk based on `||loco_cmd||`. Headless regression covered.

### Phase 3 — Non-teleop / scripted / motion-primitive

**Goal:** Closed-loop behavior without human input. State machine or motion-primitive driver feeding `navigate_cmd` + arm targets, **without** a learned policy yet.

**Direction (see `activeContext.md` for specifics):** introduce a `CommandSource` abstraction so keyboard, VR, scripted primitives, and (later) GR00T policy all plug into the runtime through one contract. First concrete primitive: keyboard-triggered "pick → lift → drop a box".

## VR debug symptom map (field reference)

| Symptom | Likely cause | Fast check / fix |
|---------|--------------|------------------|
| Constant ±90° heading mismatch | Receiver/world heading offset | Tune `--vr-receiver-yaw-deg` (default `-90`) |
| Up/down seems missing | Z clamped in overlay | Use `--debug-vr-stream-torso-z full` |
| Up/down moves in an arc (coupled with fwd/back) | Calibration includes startup HMD pitch/roll | Use `--debug-vr-stream-calib-orient yaw_only` |
| Hand translation feels wrong unless HMD is tilted | Current-HMD pitch/roll coupling in head-relative `inv(T_hmd)` | Use `--vr-head-orient yaw_only` with `--vr-ik-anchor torso` or `pelvis` |
| Drift/warp while walking + turning | Non-rigid correction placement in compose chain | Keep one rigid correction point; no partial per-device/per-term offsets |
